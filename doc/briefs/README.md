# Briefs and work orders

Every brief, work order and package this project has been given, as
Data sent it. **Content is byte for byte what arrived** — nothing
reworded, nothing shortened, nothing tidied, including the shell line
some of them open with and one stray "Dachte 4 s nach" that came along
with a copy.

## Why they are here at all

They were not. Until 9 September 2026 the only copies were Claude
Code's cache of the chat pastes, `~/.claude/paste-cache/<hash>.txt` —
hash-named, undated inside, in a directory nothing in this project
reads and nothing here would notice being pruned. A handover of that
day called four of them "in the tree"; none was, and three documents
cited briefs by filenames that had never existed. Data's decision, the
same evening: they become repository content.

## What the columns mean

**Date** is filled only where the brief's own text states one, which
is twelve of the hundred and two. Everything else is **undatiert** — not
because the order is unknown but because a date has to come from the
brief itself or from the first commit that implements it (see
CLAUDE.md, "You own every detail"), and a cache file's timestamp is
neither. The **Cached** column carries that timestamp anyway, because
it is a real fact about a real file and it is what the numbering
follows; it is not a claim about when the brief was written.

**The number prefix is order, not date.** It follows the cache
timestamps, which is the only ordering evidence there is. If one turns
out to be wrong, the fix is a line in this table — the filenames stay,
so a pointer to one keeps working.

**Source** is the cache file the content came from, or "attachment"
for the two that arrived inside the 9 September order and had no cache
entry of their own, or "session" for the ones given directly in a
Claude Code session and written here in the same run (92 onward).

**The index went stale, and now a check holds it.** On 19 September
2026 (work order 135) the table stopped at 128 while the directory held
129, 130, 131 and 134's progress and parked files, and four work-order
files — 125, 132, 133 and 134 — had never been imported at all. They
were found where this page says the only copies used to be: the paste
cache. `tools/smoke_test.py` now asserts that every file in this folder
is linked from this table and that every link resolves, in both
directions, so an import that is not indexed fails the suite instead of
being noticed a fortnight later.

**Three of those four had no filename to take.** 126 and 127 were
placed by Data as `workorder_*.md` and their names follow that; 134 was
drafted as `workorder_fleets_screen.md` and is named for it. 125, 132
and 133 arrived only as pasted text, so their names are made from their
own first line in the shape 122-124 use, and the row says which cache
file each one came from.

**A picture travels with its brief** under the brief's number:
`92-mockup.png` is the mockup brief 92 is judged against. So does a
piece of work a brief asked to be parked rather than committed:
`136-draft-fleets-opening-check.py` is the check work order 136 C asked
for and forbade adding to the suite, because it is red against today's
artwork.
